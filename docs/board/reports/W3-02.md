## `packages/db/src/queries/matches.ts` — KK-116/117

```ts
export async function getMatchHistory(
  userId: string,
  limit: number = HISTORY_PAGE_SIZE,
): Promise<MatchEntry[]>
```

Sorgu KK-117'nin İSTEDİĞİ ŞEKİLLE BİREBİR:

```ts
Game.find(
  { participants: userId, finishedAt: { $ne: null } },
  'players winner isDraw endReason rated eloDelta finishedAt',
)
  .sort({ finishedAt: -1 })
  .limit(limit)
```

`games`'in `{participants:1, finishedAt:-1}` bileşik indeksi (`DB-002`'den
beri modelde var, bu kartla eklenmedi) filtreyle BİREBİR eşleşiyor. Opponent
adı ikinci toplu bir `User.find({_id:{$in:...}})` sorgusuyla çözülüyor
(`getFriendsView`'daki N+1-önleyici desenin aynısı). `result` (`win`/
`loss`/`draw`) ve `eloDelta` (yalnız `rated` ise kendi koltuğundan, aksi
halde `null`) `GameDoc`tan TÜRETİLİYOR — kural yeniden yazılmadı, `Game`
dokümanındaki `winner`/`isDraw`/`rated`/`eloDelta` alanları (hepsi
`finishGame`, W1-02/W3-01 ürünü) okunuyor.
