# DB-005 — `seedTestUsers` `$setOnInsert` istatistikleri hiç sıfırlamıyor

## Seçilen yol: (a) — `seedTestUsers` `$set` kullanır

`packages/db/src/seed.ts`: `stats`/`elo`/`ratedGames`/`theme` artık `$setOnInsert` yerine
`$set` içinde. Seed her koştuğunda `TEST_USERS`'ı bilinen sıfır duruma **geri döndürür**.

### Gerekçe

- Seed **yalnızca** `TEST_USERS`'taki iki sabit `_id`'yi (`e2e-user-1`, `e2e-user-2`) hedefler
  (`User.updateOne({ _id: user._id }, ...)`). Filtre kullanıcı girdisinden gelmiyor, sabit
  bir literalden geliyor — gerçek oyuncu verisine dokunma riski YOK. `TEST_USERS`'ın kendi
  yorumu zaten "E2E testleri bu kullanıcılarla giriş yapar" diyor; bu iki hesap üretimde asla
  gerçek bir kişiye ait olamaz (email'ler `@xox.test`).
- (b) seçilmedi: "seed.test.ts kendi ön koşulunu kursun" testi seed'in **gerçek davranışını**
  sınamaktan çıkarır — kartın "iddia değişmemeli" kısıtına aykırı düşerdi. Asıl kusur seed'in
  KENDİSİ (idempotent reset sözü vermesi gerekirken vermemesi), testin izolasyon eksikliği
  değil.

### `$setOnInsert` başka yerde aynı tuzağı kuruyor mu?

`grep -rn '\$setOnInsert' packages/db/src` → yalnız iki yer:

1. `packages/db/src/seed.ts` — bu kart, düzeltildi.
2. `packages/db/src/queries/friends.ts:54` — **farklı sınıf, kusur DEĞİL.**
   `{ $setOnInsert: { userA, userB, status: 'pending', requestedBy: requesterId } }` bilinçli:
   arkadaşlık isteği yalnız YOKSA açılsın, var olan `pending`/`accepted` durumunu bir sonraki
   istekte SESSİZCE ezmesin (KK-125/126, dosyadaki yorum). Burada "her çağrıda bilinen duruma
   dön" değil "yalnız ilk kez oluştur, sonra dokunma" isteniyor — seed'in tersi bir sözleşme.
   Aynı testte (`friendship.test.ts`) zaten "aynı isteği iki kez göndermek durumu DEĞİŞTİRMEZ"
   doğrulanıyor. Dokunmadım.

## Kirlet → seed → yeşil sırası — gerçek çıktı

Yeni test: `packages/db/src/seed.test.ts` → `'kirlenmiş istatistikleri bir sonraki koşuda
bilinen sıfır duruma GERİ DÖNDÜRÜR'`. Kirletme, `finishGame`'in gerçek üretim yazma yolunu
birebir taklit eder (`packages/db/src/rooms/finish.ts:99-106`): `User.bulkWrite([{ updateOne:
{ filter: { _id }, update: { $inc: { 'stats.<alan>': 1 } } } }])`.

**RED (düzeltmeden önce, `$setOnInsert` ile) — gerçek Atlas `xox_test`'e karşı koşuldu:**

```
FAIL  |db| src/seed.test.ts > seedTestUsers > kirlenmiş istatistikleri bir sonraki koşuda bilinen sıfır duruma GERİ DÖNDÜRÜR
AssertionError: expected { wins: 1, losses: +0, draws: +0 } to strictly equal { wins: +0, losses: +0, draws: +0 }
 Test Files  1 failed (1)
      Tests  1 failed | 4 passed (5)
```

Mutasyonun gerçekten uygulandığı `diff` ile doğrulandı (seed.ts eski `$setOnInsert` haline
döndürülüp `diff -q` ile karşılaştırıldı) — sonda sessizce tutmadı değil.

**GREEN (düzeltmeyle, `$set` ile) — aynı sıra, aynı Atlas:**

```
✓ |db| src/seed.test.ts (5 tests) 4062ms
  ✓ TEST_USERS içindeki her kullanıcı için gerçek argon2id özeti yazar
  ✓ idempotenttir — ikinci çağrı aynı kullanıcı sayısını korur
  ✓ varsayılan profil alanlarını (elo/ratedGames/theme/stats) kurar
  ✓ kirlenmiş istatistikleri bir sonraki koşuda bilinen sıfır duruma GERİ DÖNDÜRÜR
  ✓ doğrudan çalıştırıldığında CLI girişi seedTestUsers çalıştırır ve bağlantıyı kapatır
Test Files  1 passed (1)
     Tests  5 passed (5)
```

Sıra tek koşuluk değil — kirletme her seferinde gerçek bir `$inc` yazmasıyla üretiliyor,
sonra `seedTestUsers()` tekrar çağrılıp aynı test içinde sıfırlandığı doğrulanıyor.
